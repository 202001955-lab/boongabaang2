## 계획과 현재 변경

1. 프론트 상태와 비동기 제보 처리를 수정하고 Node 회귀 검사를 추가했다.
2. 실제 브라우저·라이브러리와 모의 외부 서비스를 결합한 Playwright 테스트 및 CI를 추가했다.
3. 별도 워크트리에 이번 작업만 옮기고 원래 작업 디렉터리의 변경은 보존했다.
4. 비개발자용 문제/개선 요청 양식, PR 양식, 협업 안내를 추가했다.
5. 루트 `AGENTS.md`, `.agents/skills/`의 전달·프론트 검증 스킬, `docs/ai/` 운영·프로젝트·결정·인수인계 문서를 추가했다.

다른 디자인 작업은 별도 브랜치/PR에 있다. 이 PR과 `public/world/index.html` 변경이 겹칠 수 있으므로
병합 순서를 확인하고 의미를 보존해 충돌을 해결해야 한다. 다른 작업을 일괄 복사하거나 덮어쓰지 않는다.

별도 lint 명령은 없다. 브라우저 테스트는 세 환경의 에뮬레이션이며 실제 기기 검증은 아니다.
실제 DB/RLS·Storage·서비스 성능은 검증하지 않았다. `npm audit`에는 기존 Next/PostCSS 및
앱 CDN 버전에 맞춘 Supabase SDK 관련 경고 4건이 남아 있고 PR에 기재했다.

## 결정·제약·남은 일

- 장기 운영 결정은 [DECISIONS.md](../DECISIONS.md), 절차는 [WORKFLOW.md](../WORKFLOW.md)에 유지한다.
- 2026-11-05 작업 당시 원본 저장소는 읽기 권한이어서 접근 가능한 포크로 PR을 제출했다.
  연결 앱과 CLI의 인증 계정이 달랐다. 다음 AI는 현재 인증·원본/포크·push 권한을 다시 확인한다.
- 기존 스키마 파일에 삭제 구문과 프론트 좌표 컬럼 불일치가 있다. 실제 DB의 상태는 미확인이다.
- Vercel 미리보기는 권한 승인이 필요하다. 화면 확인은 로컬 체험 모드로 가능하며, 실제 배포 성공으로 보고하지 않는다.
- 다음 AI: 현재 브랜치/diff와 PR 최신 head·검사를 확인 → 요청자의 수정 의견 반영 → 변경 종류에 맞게 검증 → 이 기록과 PR 갱신.
- 병합이 별도로 요청되면 최신 main과 디자인 PR의 충돌·검증 영향을 확인한다. 브랜치 보호·배포 권한을 우회하지 않는다.
- 복구: 병합 전은 후속 수정 커밋, 병합 후는 승인 범위 안에서 revert PR. 공유 이력을 강제로 되돌리지 않는다.
