# 지속할 결정

결정은 이유와 적용 범위를 함께 남긴다. 변경 시 기존 결정을 조용히 삭제하지 말고 새 항목에서 대체 관계를 표시한다.
진행 상황이나 일회성 장애는 `tasks/`에 기록한다.

## D001 · main과 작업별 PR · 2026-11-05

두 사람과 각 AI의 변경을 작은 단위로 확인하기 위해 상시 develop 브랜치 없이 main에서 짧은 작업 브랜치를 만든다.
한 작업은 하나의 워크트리·PR을 기본으로 하며, 같은 PR의 합의된 후속 요청은 같은 브랜치에서 이어간다.
공유한 브랜치는 merge로 동기화하고, 저장소 설정과 승인 범위가 허용하면 PR은 squash merge한다.
세부 절차: [WORKFLOW.md](WORKFLOW.md).

## D002 · 지침과 인수인계의 저장소 관리 · 2026-11-05

다른 AI·다른 컴퓨터에서도 이어서 작업할 수 있도록 공통 지침은 루트 AGENTS.md,
반복 절차는 `.agents/skills/`, 진행 상황은 작업별 기록으로 관리한다.
개인 홈의 설정이나 대화 전문을 팀의 유일한 기억으로 사용하지 않는다.
도구별 설정은 필요성이 확인될 때 추가하며, 공통 규칙의 복사본을 여러 곳에 만들지 않는다.

## D003 · 실제 브라우저와 모의 외부 서비스 · 2026-11-05

백엔드 계정 없이 프론트 회귀를 재현하도록 실제 라이브러리·DOM·WebGL을 실행하고 HTTP·WebSocket·지도 데이터만 모의 처리한다.
이 테스트는 실제 DB 스키마·RLS·운영 배포 검증을 대체하지 않는다.
세부 범위: [E2E 안내](../../tests/e2e/README.md).

## D004 · 코드 검증과 사용자 확인 분리 · 2026-11-05

자동 검사가 통과해도 화면·문구가 요청 의도에 맞는지는 요청자가 확인한다.
AI는 PR에 변경 전·후와 따라 할 순서를 적고, 실제로 확인하지 않은 항목을 대신 승인하지 않는다.
로컬 검사·원격 CI·미리보기 배포도 구분한다. 협업 양식은 [CONTRIBUTING.md](../../CONTRIBUTING.md)를 따른다.
