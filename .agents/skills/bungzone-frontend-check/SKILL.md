# 붕세권 프론트 검증

[프로젝트 지도](../../../docs/ai/PROJECT.md), [package.json](../../../package.json),
[E2E 안내](../../../tests/e2e/README.md)를 읽고 실제 변경 범위를 확인한다.

## 검사 선택

| 변경 | 필요한 확인 |
| --- | --- |
| 문서·양식·지침·스킬만 | Markdown 링크, YAML/frontmatter, 경로·명령 일치, diff·민감정보 검토. 앱 전체 검사를 새로 했다고 주장하지 않음 |
| HTML/JS·UI/CSS·브라우저 동작 | 해당 Node 회귀 검사와 E2E로 수정 중 확인, 전달 전 `npm run test:all` |
| E2E/fixture/Playwright 설정 | 변경된 시나리오를 진단한 뒤 전달 전 `npm run test:all`로 정의된 세 환경 확인 |
| 의존성·Next 설정·빌드/CI | 잠금 파일·실제 스크립트·브라우저 자산 대응 확인, `npm run test:all`; 추가한 검사도 실행 |

`test:e2e`에는 프로덕션 빌드와 타입 검사가 포함된다. 이미 성공한 동일 코드의 빌드를 이유 없이 반복하지 않는다.
개별 `tsc`는 Next가 타입 파일을 생성한 뒤 실행한다. 별도 lint 명령은 현재 없으므로 실행한 것처럼 보고하지 않는다.

## 테스트의 경계

- E2E에서는 실제 SDK·DOM·WebGL을 실행하고 외부 네트워크만 fixture에서 제어한다.
  앱 전역 변수·함수를 바꿔 결과를 성공으로 만들지 않는다. 고정 sleep보다 화면 상태와 요청을 기다린다.
- 오류를 다룰 때 성공·실패·재시도와 관련된 기존 동작도 검증한다. 테스트를 통과시키려고 기대 결과를 임의로 약화하지 않는다.
- 좌표/렌더링의 허용 오차는 실제 변환 근거와 사용자 관점의 정확도에 맞게 정한다.
- 실제 서비스 키·DB 쓰기·개인 사진을 쓰지 않는다. CDN 버전을 바꾸면 로컬 테스트 자산과 잠금 파일도 확인한다.
- 3100 포트와 같은 워크트리의 `.next` 충돌을 확인한다. 다른 AI의 서버를 임의로 종료하지 않는다.

## 결과와 인수인계

실행 명령, 검증 대상 커밋/변경 범위, 통과·실패·미실행 결과를 작업 기록과 PR에 남긴다.
실패 시 리포트의 관찰로 원인을 좁히고 고친 범위를 다시 검사한다. 로컬에서 안 한 검사를 CI가 했다고 가정하지 않는다.
최종 설명에서 모의 API 검증과 실제 DB/RLS·배포 검증, 브라우저 에뮬레이션과 실제 기기 확인을 구별한다.
