# 붕세권 작업 전달

먼저 [AGENTS.md](../../../AGENTS.md)와 [Git 운영 규칙](../../../docs/ai/WORKFLOW.md)을 읽는다.
이 스킬은 외부 작업의 승인을 새로 부여하지 않는다. 현재 요청과 이미 받은 승인 범위 안에서 진행한다.

## 작업 식별

- 현재 branch/worktree/diff와 열린 PR을 확인한다. 다른 작업자의 변경은 보존한다.
- 같은 PR의 후속 작업이면 기존 브랜치와 작업 기록을 갱신한다. 새 작업이면 최신 base에서 별도 워크트리를 만든다.
- [작업 기록 양식](../../../docs/ai/TASK_TEMPLATE.md)을 사용해 해당 작업의 `docs/ai/tasks/` 파일을 유지한다.
  목표·범위·완료 지점·검증 근거·남은 일을 먼저 확인한다.

## 전달 전

- 변경 종류에 맞는 검증을 한다. 프론트 변경은 [프론트 검증 스킬](../bungzone-frontend-check/SKILL.md)을 따른다.
- 전체 diff를 검토한 뒤 이번 작업의 파일만 stage하고 staged diff·파일 목록·민감정보·생성물을 확인한다.
- 구조나 반복 절차가 달라졌으면 PROJECT/DECISIONS/해당 스킬 중 원본 문서를 갱신한다.
- 승인된 범위에서 커밋하고, 인증 계정과 실제 push 대상·PR base/head를 확인해 작업 브랜치만 푸시한다.
  계정·권한은 이전 세션 기록에서 고정하지 않고 현재 상태로 확인한다.
- [PR 양식](../../../.github/pull_request_template.md)을 채우고 검증과 제한 사항을 정확히 적는다.
  기존 PR은 최종 범위에 맞게 갱신한다. PR 생성만 맡았으면 병합·배포로 확장하지 않는다.

## 완료 또는 차단

원격 PR head가 푸시한 커밋과 같은지 확인한다. 실패를 테스트·CI·권한·배포로 나눠 설명한다.
작업 기록과 최종 답변에 브랜치, PR, 검증 근거, 남은 항목, 다음 행동을 남긴다.
권한 오류의 원인이 확인됐고 사용 가능한 정당한 경로가 없으면 같은 시도를 반복하지 않는다.
준비된 변경을 보존하고 필요한 권한/사용자 입력만 구체적으로 알린다.
